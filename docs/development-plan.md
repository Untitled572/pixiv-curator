# 开发计划

版本：0.3；更新日期：2026-11-12。本文是任务状态与验收的唯一来源；技术契约见[详细设计](detailed-design.md)。

## 1. 目标与当前状态

目标：关注导入 → 画师推荐 → 预览确认 → 自动维护作品目录 → 偏好选图 API → PicHub 下载、缓存、收藏与分发。

当前目录、队列、推荐、偏好和管理页面已有实现。多账号、账号来源筛选、画师标签覆盖及 JSON 固定图片地址/图片流/302 出图实现已完成。全仓 `go vet ./...`、`go test -race ./...`，Linux/Windows amd64、arm64 构建和隔离浏览器桌面/手机验证通过；当前 Windows 原生 OAuth、117 人完整关注快照、单画师采集、推荐与管理预览实网验收通过（见第 21 节）；PicHub、Docker 与远端 CI 仍未验收。

用户已确定：
- Go 为主。
- 推荐画师必须人工确认后采集。
- 本项目保存 ID、元数据与链接。
- Curator 负责带 Referer 流式转发，不缓存原图；归档交 PicHub，管理缩略图使用有界缓存。
- 单用户允许多个 Pixiv 账号；身份验证成功后建立账号，旧单账号凭据迁移为 `legacy`。
- 关注同步自动批准并安排采集，保留 `blocked` / `rejected`；推荐候选仍须人工确认。旧 `legacy` 首次以 UID 0 导入，成功同步绑定真实 UID，绑定前禁止增加第二账号。缺省手动操作使用首个账号，不换号绕过限速。
- 六小时周期从每次进程启动后重新计时，不持久化下次触发时间。
- 取关或删除账号不删除来源历史及作品目录；屏蔽画师优先排除供图。
- /random 默认 JSON 返回本服务固定图片地址并保留 original_url；format=image 输出图片，format=redirect 跳转固定图片端点，delivery=original 保留原图兼容模式。

## 2. 交付原则

- 先自动同步并采集已关注画师，建立可恢复目录，再打通供图，随后完成推荐候选的预览与人工确认流程。
- 每个任务有依赖、产物和可观察的验收结果。
- 单用户、多个 Pixiv 账号、单 Go 服务、SQLite；同一画师在多账号间共用目录。
- 不把现有多个仓库直接拼接，不在第一版引入 Redis、微服务、向量检索、多账号代理池。
- 公网部署不在初始化交付范围；管理鉴权必须先于实际账号接入完成。
- 时间与性能结论在样本规模明确后测量，不用未经验证的容量数字承诺上线。

状态：已完成 / 待开始 / 进行中 / 阻塞。只有验证完成才标为“已完成”；阻塞需记录原因和解除条件。

## 4. 第一版范围

M1–M4 是满足用户完整流程的第一版。M3 是可提前使用的最小接入版本。

包含：多 Pixiv 账号及关注来源、画师人工确认、静态插画/漫画分页目录、基础推荐、偏好筛选、标签/账号图源筛选、固定图片流/URL/302 图源接口、四页管理界面。

暂不包含：Curator 原图归档和磁盘缓存、ugoira 视频转换、跨用户推荐、视觉 embedding、复杂多账号路由、完整复制参考站全部参数与页面。

## 5. 验证矩阵

| 风险 | 验证方式 | 通过标准 |
| --- | --- | --- |
| 重复入库 | 重放相同作者/分页响应 | 作品与图片页数量不增加 |
| 中断恢复 | 扫描一半终止、重启、重复投递 | 游标继续；已写页不丢；无重复事件 |
| 审核绕过 | 未确认/拒绝/屏蔽画师的样本混入目录 | API 始终不返回这些样本 |
| 内容分类未知 | 构造缺失或非法 AI/R18 字段 | 默认筛选排除未知，界面标为待补全 |
| 图像身份混淆 | 对同 /i 路径重复请求 | 同一作品页；不发生第二次随机选择 |
| PicHub 二跳 | JSON 选图后由 PicHub 下载 | Referer/网络可达；Curator 不生成原图文件 |
| 故障扩散 | mock 401/429/5xx/超时 | 有限重试，账号冷却，无忙循环 |
| SSRF/凭据泄漏 | 非白名单 URL、重定向、错误响应 | 拒绝目标且无 token 输出或转发 |
| 并发去重 | 多个同时选图请求 | 原子预留；可用范围不足有定义的降级 |
| 误学偏好 | 模拟 PicHub 预取与显式喜欢 | 仅显式操作改变偏好 |
