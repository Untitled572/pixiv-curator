# 开发计划

版本：0.1；更新日期：2026-10-08。本文是任务状态与验收的唯一来源；技术契约见 [详细设计](detailed-design.md)。

## 1. 目标与当前状态

目标：关注导入 → 画师推荐 → 预览确认 → 自动维护作品目录 → 偏好选图 API → PicHub 下载、缓存、收藏与分发。

当前已实现 M1–M4 的核心业务代码和管理页面，离线/mock 测试覆盖关注、采集、补全、推荐预算与恢复、人工批准隔离、选图和固定图片代理。真实 Pixiv/PicHub 联调与本轮 Docker 验证尚未完成，M3/M4 完整目标流程仍保持进行中。

用户已确定：
- Go 为主。
- 推荐画师必须人工确认后采集。
- 本项目保存 ID、元数据与链接。
- 原图文件由 PicHub 管理。

## 2. 交付原则

- 先确认导入的已关注画师并建立可恢复目录，再打通供图，随后完成推荐候选的预览与人工确认流程。
- 每个任务有依赖、产物和可观察的验收结果。
- 第一版单用户、单 Pixiv 账号、单 Go 服务、SQLite。
- 不把现有多个仓库直接拼接，不在第一版引入 Redis、微服务、向量检索、多账号代理池。
- 公网部署不在初始化交付范围；管理鉴权必须先于实际账号接入完成。
- 时间与性能结论在样本规模明确后测量，不用未经验证的容量数字承诺上线。

状态：已完成 / 待开始 / 进行中 / 阻塞。只有验证完成才标为“已完成”；阻塞需记录原因和解除条件。

## 4. 第一版范围

M1–M4 是满足用户完整流程的第一版。M3 是可提前使用的最小接入版本。

包含：单账号、关注导入、画师确认、静态插画/漫画分页目录、基础推荐、偏好筛选、固定图片代理、JSON 图源接口、管理页面。

暂不包含：自动关注 Pixiv、原图全量下载、ugoira 视频转换、跨用户推荐、视觉 embedding、复杂多账号路由、完整复制参考站全部参数与页面。

## 5. 验证矩阵

| 风险 | 验证方式 | 通过标准 |
| --- | --- | --- |
| 重复入库 | 重放相同作者/分页响应 | 作品与图片页数量不增加 |
| 中断恢复 | 扫描一半终止、重启、重复投递 | 游标继续；已写页不丢；无重复事件 |
| 审核绕过 | 未确认/拒绝/屏蔽画师的样本混入目录 | API 始终不返回这些样本 |
| 内容分类未知 | 构造缺失或非法 AI/R18 字段 | 默认筛选排除未知，界面标为待补全 |
| 图像身份混淆 | 对同 /i 路径重复请求 | 同一作品页；不发生第二次随机选择 |
| PicHub 二跳 | JSON 选图后由 PicHub 下载 | Referer/网络可达；Curator 不生成原图文件 |
| 故障扩散 | mock 401/429/5xx/超时 | 有限重试，账号冷却，无忙循环 |
| SSRF/凭据泄漏 | 非白名单 URL、重定向、错误响应 | 拒绝目标且无 token 输出或转发 |
| 并发去重 | 多个同时选图请求 | 原子预留；可用范围不足有定义的降级 |
| 误学偏好 | 模拟 PicHub 预取与显式喜欢 | 仅显式操作改变偏好 |
