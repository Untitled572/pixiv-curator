# Pixiv Curator

Pixiv Curator 是一个用 Go 编写的本地 Pixiv 画师与作品目录服务。它同步关注关系、采集作品元数据，并按筛选条件返回固定图片页或图片地址，可供浏览器及 PicHub 等消费端使用。

## 功能

- 管理多个 Pixiv 账号，分别保存账号凭据与公开、私密关注来源；同一画师共享一份本地图库。
- 完整关注同步发现的画师会自动批准并加入采集；`blocked` 和 `rejected` 状态保留。推荐画师先展示代表作，只有用户明确批准后才加入图库。远端关注默认关闭。
- 统计作品、图片分页和图库状态。R18 图片分页数合并统计 `r18` 与 `r18g`；比例分母是全部图片分页，未知分级也计入分母。
- 在图库整理页抽查已批准画师，并将不再采集的画师设为暂停。移出与暂停均停止采集和供图，删除作品、图片链接及关联分发历史和反馈，保留画师与账号来源，不会在 Pixiv 取关。
- 查看分发历史，并按图片分页记录赞、踩或撤销反馈。反馈对作品标签产生轻微抽样偏置；踩过的分页按规则排除。
- `unknown` 分级和 AI 分类保持独立；默认排除，只有全局偏好允许后才能筛选未知值。
- 原图按请求从 Pixiv 流式转发，不落盘。管理缩略图可以使用有界缓存。

## 快速开始

### Windows 发行包

从 [GitHub Releases](https://github.com/Untitled572/pixiv-curator/releases) 下载对应架构的 Windows ZIP，解压后运行 `start.cmd`。发行包自带 EXE，不需要安装 Go。源码目录中的 `start.cmd` 会构建 EXE，需要 Go 1.26 或更新版本。

### Linux 发行包

从 Releases 下载对应架构的 `.tar.gz` 并解压。二进制默认使用 `data/curator.db` 并监听 `127.0.0.1:5722`。管理操作需要管理令牌文件；添加 Pixiv 账号还需要 OAuth 应用配置。若服务要供其他设备访问，应把 `PIXIV_CURATOR_PUBLIC_BASE_URL` 设为客户端可访问的地址。环境变量、私密文件和权限要求见[运行与接入](docs/running.md)。

发行压缩包包含 `pixiv-curator` 可执行文件和配置说明。准备好私密配置后，可按运行文档设置环境变量并启动：

```sh
./pixiv-curator
```

### 从源码运行

需要 Go 1.26 或更新版本。Linux 使用：

```sh
./scripts/dev.sh
```

Windows 使用 PowerShell 5.1 或 PowerShell 7：

```powershell
.\scripts\dev.ps1
```

开发脚本默认监听 `127.0.0.1:5722`，数据保存在 `data/dev`，并准备管理令牌。第一次启动且缺少 OAuth 应用配置时，需要 Python 3 来生成配置；这一步不登录 Pixiv。进入管理页后，在“设置 → Pixiv 账号”输入 Refresh Token，服务验证账号身份后保存。已有 OAuth 配置时，日常启动不需要安装登录依赖。启动选项和其他环境变量见[运行与接入](docs/running.md)。

### Docker Compose

Linux 部署模板见 [`deploy/compose.yml`](deploy/compose.yml)。该模板使用 host 网络，运行前需要准备持久数据目录、私密 OAuth 配置、管理令牌和账号凭据。目录权限、监听地址及备份步骤见[运行与接入](docs/running.md)。

## 管理与账号

浏览器打开服务的 `/admin/login`，使用管理令牌登录。Windows 启动脚本会在 `data/dev/admin-token` 保存令牌；发行包或服务器部署则通过 `PIXIV_CURATOR_ADMIN_TOKEN_FILE` 指定私密文件。令牌、OAuth 配置和 Refresh Token 不应提交到 Git，也不要放入公开目录。

管理页面有五个页签：

- **统计与接口**：查看本地目录统计，并生成选图请求。R18 比例统计 `r18` 和 `r18g` 图片分页，分母包含所有分级的分页。
- **发现画师**：预览推荐画师和代表作；需要用户确认才会加入图库。
- **分发历史**：查看记录过的固定作品页，并为单页设置赞、踩或中性反馈。重复出现的同一图片页显示同一反馈。
- **画师图库**：按账号和标签筛选画师、编辑标签、整理采集名单。移出图库与暂停采集行为相同：停止采集和供图，清理作品目录、链接和关联历史；恢复后重新采集。画师及账号来源保留，不会远端取关。
- **设置**：管理 Pixiv 账号、选图偏好和服务端网络配置。

桌面主管理界面使用 110% 缩放，手机布局保持原样。

账号关注同步会分别读取公开和私密关系。关闭“批准后远端关注”时，服务不会因推荐批准而发起关注；显式复制关注也不会执行取关。删除账号会移除凭据并隐藏账号筛选入口，账号来源关系和历史目录继续保留。

## 推荐、探索与反馈

每轮最多以 30 位候选为目标：17 位算法候选、10 位独立历史榜单随机候选、3 位随机 ID 探测候选。两类独立探索不读取本地画像或算法分数，结果会与算法候选混排。若候选重叠或来源数量不足，会按实际可用来源补位；全轮仍受 80 次请求预算限制。

算法使用轻量 L2 正则逻辑回归，输入为 512 维哈希标签特征和官方推荐来源特征，不使用视觉信息。训练只读取当前已批准和已拒绝画师的选择；待审、屏蔽和单纯曝光不作为负例。上一成功轮新批准的正例权重为 0.2，其余样本权重为 1，并平衡正负类别总权重、使用 L2 正则控制过拟合。

模型分数用于候选排序，不是经校准的喜欢概率。缺少正例或负例时，模型保持中性冷启动，由现有图库类型分布参与排序。探索候选显示的“推荐指数”只供展示位置参考，不参加模型训练或候选排序。

历史榜单探索从 Pixiv 榜单来源独立抽取，不按本地画像或模型评分挑选。随机 ID 探测使用当轮近期全站日榜中的最大作品 ID 作为编号上界，在编号范围内均匀抽取；空号、已删除或当前账号无权访问的作品会跳过。因此这两类探索都不代表在全站画师范围内严格均匀抽样。

历史赞踩按图片分页保存。赞踩只通过作品标签产生轻微的抽样权重变化；以单一共同标签为例，约 50 次净同类反馈才达到二选一约 5 个百分点的变化量级，实际排序不保证按固定次数改变。踩过的图片分页仍优先硬排除；这些软反馈不会作为逻辑回归训练标签。

## 图片 API

`GET /random` 默认返回 JSON，`url` 是 Curator 的固定图片页地址，消费端直接请求该地址即可；Curator 会携带 Pixiv Referer 获取图片。

```sh
# 默认 JSON
curl 'http://127.0.0.1:5722/random'

# 仅选择 R18 / R18G；页面直接返回图片
curl 'http://127.0.0.1:5722/random?r18=1&format=image'

# 固定图片页，不重新随机选择
curl 'http://127.0.0.1:5722/i/12345678/0?format=image'
```

常用参数：

| 参数 | 用法 |
| --- | --- |
| `format=json` | 返回选中图片的信息，默认值。 |
| `format=image` | 直接流式返回图片。 |
| `format=redirect` | 302 到本服务的固定图片页地址。 |
| `r18=0` | 仅全年龄分级。 |
| `r18=1` | 选择 `r18` 或 `r18g`。 |
| `r18=2` | 选择所有已知分级。 |
| `r18=unknown` | 选择未知分级；仅当全局偏好允许未知值时有效。 |
| `ai_type=0` / `1` | 分别选择非 AI / AI。 |
| `ai_type=any` / `unknown` | 所有已知 AI 状态 / 未知 AI 状态；未知值仍受全局偏好限制。 |

还可使用 `account_id`、`included_tags`、`orientation`、`min_width`、`min_height` 和 `exclude_manga` 组合筛选。屏蔽、显式踩图和其他硬排除不会被请求参数放宽。`format=redirect` 和默认 JSON 不会先下载图片；只有图片请求会拉取图像字节。`delivery=original` 保留旧式原图地址模式，消费端需自行处理 Pixiv 图片访问要求。
